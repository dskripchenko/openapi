# AsyncAPI

Событийные API, описанные в AsyncAPI 2.x (2.0–2.6) или 3.0, читаются и
показываются так же, как спецификации OpenAPI.

## На странице

```vue
<script setup lang="ts">
import { AsyncApiReference } from '@dskripchenko/openapi/vue'
import '@dskripchenko/openapi/style.css'
</script>

<template>
  <AsyncApiReference :spec="yamlOrJsonText" locale="ru" />
</template>
```

Страница показывает описание документа и серверы (протокол, адрес,
переменные), затем операции, сгруппированные по тегам — или по каналам, если
тегов нет ни у одной операции. У каждой операции видно, **отправляет**
приложение или **принимает**, адрес канала с выделенными `{параметрами}`,
параметры, каждое сообщение (схемы заголовков и содержимого, тип содержимого,
идентификатор корреляции, пример — из документа или построенный по схемам — и
привязки), ответ операции «запрос–ответ» (3.0) и привязки операции. Дальше
идут сообщения и схемы из компонентов. Схемы показываются тем же видом, что в
справочнике OpenAPI.

Содержимое на другом языке схем (Avro, Protobuf, RAML…) показывается как
есть, с указанием формата.

| Свойство   | Тип                      | Значение                                          |
| ---------- | ------------------------ | ------------------------------------------------- |
| `spec`     | `string \| object`       | Документ: текст YAML или JSON либо разобранный объект |
| `locale`   | `string`                 | `en` или `ru`; по умолчанию — язык браузера       |
| `labels`   | `Partial<AsyncApiLabels>`| Замена текстов                                    |
| `external` | `(url) => unknown`       | Загружает документы, на которые `$ref` ссылается по адресу |

Слоты: `actions` (в шапке) и `footer`.

## В коде

```ts
import { loadAsyncApi, detectSpecKind } from '@dskripchenko/openapi'

detectSpecKind(parsed) // 'asyncapi' | 'openapi' | null
const spec = loadAsyncApi(text)
spec.operations // [{ id, action: 'send' | 'receive', channel, messages, reply, bindings, … }]
spec.channels // [{ id, address, parameters, messages, servers, … }]
spec.servers // [{ id, url, protocol, variables, … }]
```

Обе версии приводятся к одному виду. AsyncAPI 2.x описывает операции со
стороны клиента; они разворачиваются к стороне приложения, как в 3.0: канал,
на который приложение «подписано» (`subscribe`), — тот, куда оно
**отправляет**, а `publish` — это **приём**. Применяются трейты сообщений и
операций, разворачиваются `$ref`, а сообщение, на которое ссылаются из
нескольких мест, — один и тот же объект. В `warnings` — то, что не удалось
разрешить.
