# Глубокие ссылки и предзаполненные ссылки

Справочник читает два вида адресов: ссылки на раздел и ссылки, которые
открывают операцию с уже заполненной формой try-it.

## Якоря разделов

Собственные якоря справочника — это id элементов его разделов:

| Якорь | Открывает |
|---|---|
| `#operation/{id}` | операцию — `{id}` это `operationId` или слаг вроде `get-pets-id` |
| `#schema/{name}` | схему из `components.schemas` |
| `#tag/{name}` | раздел тега |

Когда на странице [несколько спецификаций](reference.md#несколько-спецификаций),
каждый якорь начинается с id спецификации — `#v1/operation/getPet`, — а
`#v1` сам по себе открывает эту спецификацию.

Адрес читается при открытии страницы и при каждом последующем изменении
hash. С `hashNavigation` (по умолчанию) щелчок в навигации записывает якорь
раздела в адрес, а в заголовке каждой операции есть кнопка, копирующая
ссылку на неё.

## Ссылки Scalar

Понимаются и ссылки, построенные для страницы Scalar, поэтому существующие
ссылки — из `DocLink` laravel-api, из его плагина для IDE, из закладок —
после перехода продолжают работать:

| Форма Scalar | Открывает |
|---|---|
| `#[{doc}/]tag/{tagSlug}/{METHOD}{path}` | операцию с этим методом и путём |
| `#[{doc}/]tag/{tagSlug}` | раздел тега |
| `#[{doc}/]model/{name}` | схему |

Например, `#v1/tag/pets/GET/pets/{id}` открывает `GET /pets/{id}`
спецификации `v1`.

Как сопоставляются части:

- **Сегмент документа** указывает на спецификацию, id которой ему равен, а
  иначе — на спецификацию, id или название которой после слагификации по
  правилу Scalar ему равны (для версий точки и косые черты становятся
  дефисами, так что спецификация с названием `v1.1` отзывается на `v1-1`).
  Сегмент, который не называет ни одной спецификации, но стоит перед
  разделом — `v1/tag/…` на странице с одной спецификацией, —
  игнорируется, и имеется в виду открытая спецификация.
- **Имена тегов и схем** сравниваются по слагу: `Pet Store` совпадает с
  `pet-store`.
- **Путь** совпадает с путём операции или с этим путём, перед которым стоит
  base path сервера (или наоборот), так что ссылка, построенная по полному
  URI `/api/v2/pets`, находит `/pets` в спецификации с сервером `…/api/v2`.
  Если операция не найдена, ссылка открывает её тег.

С `hashNavigation` адрес затем заменяется каноническим якорем, так что при
перезагрузке или копировании получается собственная форма справочника.

`scalarSlug(text)` и `scalarDocumentSlug(version)` — правила слагов —
экспортируются из `@dskripchenko/openapi`, чтобы строить такие ссылки в
других местах.

## Предзаполненные ссылки

Предзаполненная ссылка открывает операцию с заполненной формой try-it:
параметрами, телом, сервером и, по желанию, учётными данными. **Сама по себе
она ничего не отправляет**: читатель видит уведомление — «Form filled from a
link — check the values before sending» — рядом с заполненной формой, к
которой страница прокручивает, и нажимает «Send», когда готов.

### Copy link

В панели try-it каждой операции есть кнопка «Copy link»: она копирует
предзаполненную ссылку с формой в текущем виде, включая собственные строки
query, заголовков и кук. Учётные данные в неё не
попадают, если не отмечено «Include credentials» — по умолчанию выключено,
с предупреждением, что любой, кто получит ссылку, сможет ими
воспользоваться.

Чтобы ссылки были короткими, кодировщик опускает то, что страница заполнит
сама: пустые значения, первый сервер (индекс 0) и переменные сервера со
значениями по умолчанию, первый тип содержимого и тело, равное
сгенерированному примеру. Файлы в ссылке никогда не передаются.

Когда форма заполнена, адрес заменяется простым якорем операции (при
`hashNavigation`), так что перезагрузка не заполняет её снова, а учётные
данные уходят из адресной строки.

### Формат

Формат стабилен, версия 1. Такие ссылки могут строить и другие инструменты —
laravel-api делает это на PHP.

```text
{page}#{anchor}?f={payload}        the payload in the hash
{page}?oa-f={payload}#{anchor}     or as a query parameter (the hash wins)
```

`{anchor}` — якорь операции, канонический (`[{spec}/]operation/{id}`) или в
форме Scalar (`{doc}/tag/{tag}/{METHOD}{path}`). `{payload}` — один символ и
base64url (RFC 4648 §5, без дополнения):

- `z` + base64url от UTF-8 JSON, сжатого raw DEFLATE (RFC 1951), —
  `CompressionStream('deflate-raw')` в браузере, `gzdeflate()` в PHP;
- `j` + base64url от самого UTF-8 JSON.

JSON:

```json
{
  "v": 1,
  "server": 0,
  "vars": { "region": "us" },
  "path": { "id": "42" },
  "query": { "limit": "10" },
  "header": { "X-Trace": "abc" },
  "cookie": { "session": "…" },
  "mediaType": "application/json",
  "body": "{\"name\":\"Rex\"}",
  "auth": { "bearerAuth": "token", "basicAuth": { "username": "u", "password": "p" } },
  "xQuery": [["debug", "1"]],
  "xHeader": [["X-Request-Id", "42"]],
  "xCookie": [["theme", "dark"]]
}
```

| Ключ | |
|---|---|
| `v` | Версия: `1`. Обязателен. |
| `server` | Индекс в списке серверов операции или URL сервера. URL, совпадающий с одним из серверов (как записан или с подставленными `vars`), выбирает его; любой другой URL становится собственным сервером. |
| `vars` | Переменные сервера. |
| `path`, `query`, `header`, `cookie` | Значения параметров как набраны, строками, по имени параметра (имена заголовков — в любом регистре). |
| `mediaType` | Тип содержимого тела, если операция его принимает. |
| `body` | Текст тела как набран. |
| `auth` | Учётные данные по имени схемы безопасности: ключ или токен либо `{ username, password }`. |
| `xQuery`, `xHeader`, `xCookie` | Параметры query, заголовки и куки, которых нет в спецификации, — собственные строки формы try-it — парами `[name, value]`, по порядку. |

Все ключи, кроме `v`, необязательны, неизвестные ключи игнорируются. Числа и
логические значения среди значений читаются как их текст; прочие значения
отбрасываются. Полезная нагрузка, которая испорчена, распаковывается больше
чем в 1 МБ или имеет `v`, отличную от 1, игнорируется (более поздняя версия —
с предупреждением в консоли), и ссылка просто открывает операцию. Ключи `x*`
добавлены в версию 1 без её изменения: читатель, который их не знает,
игнорирует их, а ссылки без них читаются как раньше.

На PHP:

```php
$data = [
    'v' => 1,
    'path' => ['id' => '42'],
    'body' => '{"name":"Rex"}',
    'xHeader' => [['X-Request-Id', '42']],
];
$payload = 'z' . rtrim(strtr(base64_encode(gzdeflate(json_encode($data, JSON_UNESCAPED_UNICODE|JSON_UNESCAPED_SLASHES))), '+/', '-_'), '=');
$link = "https://example.com/docs#v1/operation/updatePet?f={$payload}";
```

`path`, `query`, `header`, `cookie`, `vars` и `auth` — ассоциативные массивы
(объекты JSON); `xQuery`, `xHeader` и `xCookie` — списки двухэлементных
списков (массивы JSON): ассоциативный массив там превратился бы в объект и
был бы проигнорирован.

На TypeScript, с ядром:

```ts
import { encodePrefill, prefillHash } from '@dskripchenko/openapi'

const payload = await encodePrefill({ v: 1, path: { id: '42' } })
const link = `https://example.com/docs#${prefillHash('v1/operation/updatePet', payload)}`
```

`encodePrefill(data, { compress? })` делает полезную нагрузку `z`, где есть
`CompressionStream`, и `j` в остальных случаях; `decodePrefill(payload)`
возвращает данные или `null`; `prefillHash(anchor, payload)` даёт
`{anchor}?f={payload}`. `PREFILL_VERSION` равен `1`; типы — `PrefillData` и
`PrefillValues`.

## Функции ядра

Все экспортируются из `@dskripchenko/openapi`:

| | |
|---|---|
| `splitLink(hash)` | `{ anchor, payload? }`: якорь (раскодированный) и полезная нагрузка `?f=` из hash. |
| `pickSpec(anchor, specs)` | `{ spec?, rest }`: какую спецификацию из `LinkSpec[]` (`{ id, name? }`) называет сегмент документа, и остаток якоря. |
| `resolveSection(rest, spec)` | Канонический раздел загруженной спецификации — `operation/{id}`, `schema/{name}` или `tag/{name}` — для нашей формы или формы Scalar, либо `null`. |
| `scalarSlug(text)`, `scalarDocumentSlug(version)` | Правила слагов Scalar. |
| `encodePrefill`, `decodePrefill`, `prefillHash`, `PREFILL_VERSION` | Предзаполненные ссылки, см. выше. |
